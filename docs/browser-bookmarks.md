# notewrench browser-bookmarks

Moving bookmarks between browsers or into linkding usually means importing several
Netscape-HTML exports that overlap, and importers quietly keep one copy of a duplicate
URL and drop the other copy's notes, description or tags. `notewrench browser-bookmarks`
scans browser exports (Firefox, Chrome, Safari, ...) and linkding HTML exports
together **before** you import them, shows every duplicate group field by field, and
requires an explicit **merge** or **keep all** decision per group. The result is one
importable `bookmarks.html` plus receipts that keep every original note, tag, value and
byte-exact source file.

**Which command?** Use `browser-bookmarks` for browser bookmark HTML exports and
linkding HTML exports, when you want to decide each duplicate group yourself before
importing into linkding or a browser. For Karakeep and Wallabag read-later JSON
exports, use [`notewrench links`](links.md). After the import or any other migration,
compare the export from before with the export from after using
[`notewrench bookmark-migration`](bookmark-migration.md).

It is a small, offline pre-import adapter: it reuses linkding's MIT HTML exporter and
Beautiful Soup/html5lib rather than replacing linkding, buku or your browser. No URL is
fetched, no server, account or browser automation is involved, and your exports are
never modified.

Formerly the standalone `bookmark-receipts` tool. On-disk formats are unchanged:
review bundles (`bookmark-receipts/review-v1`), receipts (`bookmark-receipts/receipt-v1`)
and export manifests (`bookmark-receipts/manifest-v1`) written by the standalone tool
load and verify as before.

**Install:** the parsers come from an optional extra:

```sh
pip install 'notewrench[browser-bookmarks]'
```

It adds Beautiful Soup, html5lib, webencodings, filelock and ijson.
Without it, `notewrench browser-bookmarks --help` still works and every other
invocation prints that install line.

**Reads / writes:** reads only the export files named on the command line. `scan`
creates a new review directory (`review.json`, `review.html` and a copy of every input
under `sources/`); `decide` and `review` update only the decisions in `review.json`
(and refresh `review.html`); `apply` creates a new result directory. Existing output
directories are never overwritten.

**Platforms:** Linux and macOS, Python 3.11+; Windows is not supported.

## Quick start

From a clone of the repository, scan the bundled samples: real Firefox and Chrome
exports (from the bookmarks-parser test suite) and a linkding export generated by
linkding's own exporter with two conflicting snapshots of one URL:

```sh
notewrench browser-bookmarks scan \
  --html examples/browser-bookmarks/firefox.html examples/browser-bookmarks/chrome.html \
  --linkding examples/browser-bookmarks/linkding.html \
  --out .demo/bookmarks/review

notewrench browser-bookmarks show .demo/bookmarks/review
notewrench browser-bookmarks review .demo/bookmarks/review
```

`scan` prints a JSON status line: 19 original bookmarks, 4 duplicate groups, all
pending. Open `.demo/bookmarks/review/review.html` for a read-only view with one column
per source record and conflicting fields highlighted; it never activates bookmark
URLs or loads icons. The terminal reviewer (`review`) saves each completed group, so
quitting is resumable: press `m` to merge, `k` to keep every duplicate, `s` to defer or
`q` to quit. After `m`, accept or change each proposed field.

Non-interactive workflows can edit **only** `groups[].decision` in `review.json`, or
use `decide`:

```sh
# An explicit policy decision for this small sample, after inspecting show/review.html:
notewrench browser-bookmarks decide .demo/bookmarks/review --all --action merge

notewrench browser-bookmarks compat .demo/bookmarks/review
notewrench browser-bookmarks apply .demo/bookmarks/review --out .demo/bookmarks/result
notewrench browser-bookmarks verify .demo/bookmarks/result
```

`apply` writes 15 bookmarks (the 4 merged groups plus 11 singletons). Import
`.demo/bookmarks/result/bookmarks.html` with the destination's own import UI; keep
`receipts.json` and `originals/` with it.

`notewrench doctor` recognizes these exports too: `notewrench doctor
examples/browser-bookmarks` counts the duplicate groups without writing anything and
suggests a matching `scan` command.

## Commands

| Command | What it does |
| --- | --- |
| `scan --html FILE... --linkding FILE... --out DIR` | copy and parse the exports into a new review bundle; at least one input |
| `status REVIEW` | count sources, records, groups, duplicate groups and pending decisions |
| `show REVIEW [--group ID] [--include-singletons]` | print every original field value of each duplicate group |
| `review REVIEW` | decide pending groups interactively (needs a terminal) |
| `decide REVIEW (--group ID ... \| --all) --action merge\|keep\|pending [--field FIELD=CHOICE ...]` | record decisions; `--all` applies to every duplicate group |
| `compat REVIEW` | check the decided output against pinned linkding v1.47.0 URL/tag rules |
| `render REVIEW` | rebuild `review.html` after manual JSON edits |
| `apply REVIEW --out DIR` | write the result bundle; refuses while any duplicate group is pending |
| `verify REVIEW_OR_RESULT` | verify a review's copied inputs, or a result bundle's manifest and mappings |

`REVIEW` is the review directory or its `review.json`. Exit status: 0 success; 2
invalid input, a pending group at `apply`, or an existing output directory (also
argparse usage errors); 130 interrupted (completed decisions stay saved).

`compat` reports URL pairs this conservative tool keeps separate but linkding may
collapse, tag spelling changes, legacy archive markers and URL/title limits. The same
report is included in `receipts.json`; it is not a full Django import simulation, and
browser importers have their own behavior.

`decide` and the terminal reviewer use a file lock plus an optimistic revision check:
a stale copy fails instead of silently erasing another edit. Reload and repeat the
decision after a conflict, and avoid concurrent manual edits. Decision JSON is
authoritative; if a crash interrupts the HTML refresh, `render` rebuilds the view.
Changing a copied source, the snapshot or a group's membership is detected. Piped
output (for example `show ... | head`) can be stopped normally.

## Field choices

Use `--group g-…` (ID from `show`) instead of `--all` for one group, and repeat
`--field` to override defaults:

```sh
notewrench browser-bookmarks decide REVIEW/review.json --group g-CLUSTER_ID --action merge \
  --field title=@s3:2 --field notes=all --field tags=union \
  --field 'folder={"value":["Research","To read"]}'
```

The same choice values are accepted in the interactive reviewer and in JSON:

| Field | Default merge choice | Other choices |
| --- | --- | --- |
| URL, title, folder | `@s1:1` (first record in that group) | `@record_id`, `{"value":…}` |
| description, notes | `all`: distinct text blocks with contributing record IDs | `@record_id`, `{"value":"…"}` |
| tags | `union`: exact, case-sensitive union in source order | `@record_id`, `{"value":["…"]}` |
| added | `earliest` | `@record_id`, `{"value":"…"}` or null |
| modified | `latest` | `@record_id`, `{"value":"…"}` or null |
| private | `safest`: private if any source is private or unspecified | `@record_id`, `{"value":"0"}` / `"1"` / null |
| toread | `any`: unread if any source is unread | `@record_id`, `{"value":"0"}` / `"1"` / null |

`keep` exports each original bookmark separately and ignores merge field proposals.
Choosing one note, title or tag set, or a custom value, never removes the alternatives
from the receipt. `--action pending` reopens a decision. The snapshot checksum guards
against accidental edits; it is not a cryptographic signature.

## Matching policy

For HTTP(S), only the scheme and host are lowercased, a default port is omitted and an
empty path is treated as `/`. Everything else stays significant: **HTTP versus HTTPS**,
path case, trailing slash, percent spelling, query order, tracking parameters,
fragments, empty `?`/`#` delimiters and Unicode/punycode spelling. Credentials, unusual
hosts, malformed URLs, URLs with whitespace, bookmarklets and other schemes are matched
as exact strings only. There is no fuzzy title matching and no redirect check. This is
deliberately stricter than `notewrench links`, which normalizes tracking parameters.

## Result bundle

- `bookmarks.html`: Netscape HTML with linkding note markers and the selected folders.
  Every anchor has a stable `DATA-RECEIPT` ID matching the mapping files.
- `receipts.json`: complete parsed originals, source hashes, decisions, warnings,
  final field values and source-record → output mappings. This is the exact-value
  authority; keep it with the HTML.
- `sources.csv`: one row per original bookmark pointing to its output. Cells that look
  like spreadsheet formulas are prefixed with an apostrophe; the JSON keeps exact text.
- `originals/sN.html`: byte-for-byte copies of every input, including folder metadata,
  icons and fields the destination format cannot express.
- `manifest.json`: SHA-256 checks for all result files. `verify` also reparses the
  originals, requires every original to map exactly once, and cross-checks CSV
  mappings and every projected HTML field, including note text and tags. It rejects
  missing, untracked or symlinked files.

No live data is changed. Linkding's importer has its own normalization and duplicate
policy: a decision to keep two bookmarks does not force linkding to retain both. The
merged HTML also imports into other managers; a check with buku 5.1 kept both
conflicting notes with their source labels (buku normalizes tag spelling; receipts keep
the exact tags).

## Limits and format boundaries

- Linkding input means its **Netscape HTML export**, not its API JSON, a database
  backup or an asset archive. Browser input also means Netscape HTML.
- Safari-style exports without an outer `DL` are supported when they declare the
  Netscape bookmark DOCTYPE. Nested folders and Reading List folder names are kept;
  special folder identifiers remain in the byte-exact originals.
- UTF-8, declared legacy encodings and BOM-marked UTF-16 are supported. Invalid bytes
  fail explicitly instead of being replaced silently.
- Inputs must be regular files; pipes, devices and directories are rejected before
  reading. A disk error leaves a new result unpublished. A failed decision write leaves
  either the complete old or the complete new JSON.
- Limits: 8 MiB per input, 32 MiB total, 32 files. Before building the HTML5 DOM:
  25,000 anchors, 100,000 start tags, 128 nested `DL`s and 256 container levels per
  input. A review holds at most 25,000 bookmarks and 32 MiB of expanded record JSON.
  Split inputs when a limit is hit.
- Review/receipt JSON and merged HTML are capped at 64 MiB each. JSON is checked with
  streaming events before Python objects are built (128 nesting levels, 650,000
  containers, 5 million events, 32 MiB per string). The check uses ijson's pure-Python
  backend explicitly: the native `yajl2_c` backend of ijson 3.6.0 crashed on a
  5,000-digit integer in a local probe. Custom values are capped at 8 MiB serialized.
- A static `review.html` larger than 128 MiB ends with a size-limit notice; `show`,
  `review`, the JSON and the source copies still contain every field.
- Selected folder paths are rebuilt. Empty folders, folder notes/attributes, favicons,
  keywords and other anchor attributes stay in originals and receipts but are not
  projected into the merged HTML. A folder name containing `/` stays one folder.
- Descriptions are extracted as text; the original `DD` markup and exact source files
  are retained. If browser mode finds linkding note markers, the review warns you to
  use `--linkding` instead of guessing the format. Literal `[linkding-notes]` markers
  inside text are ambiguous in linkding's format and are reported.
- Date comparison uses linkding v1.47.0's seconds/milliseconds/microseconds fallback.
  Selected source spellings stay verbatim; nonstandard dates produce a warning.
- Keep review and result bundles private: they contain your bookmarks, notes and
  original file paths.

Performance (one process, synthetic linkding-format inputs): 10,000 bookmarks in two
files (5,000 duplicate groups) took about 1.8 s to scan, 1.5 s to decide, 1.4 s to
apply and 2.6 s to verify, with about 240 MiB peak RSS. Reproduce with
`python benchmarks/browser-bookmarks/benchmark.py --groups 5000` (needs the extra).

## Python API

```python
from pathlib import Path
from notewrench.browserbookmarks.review import create_review, load_review, status
from notewrench.browserbookmarks.merging import apply_review
from notewrench.browserbookmarks.verification import verify_export
```

`notewrench.browserbookmarks.parsing.parse_html(data, source_id, "html" | "linkding")`
parses one export without writing anything; `review.groups_for(records)` groups the
records by the matching policy above.
