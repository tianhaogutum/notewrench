# Fixture provenance

- `firefox.html`: unmodified `tests/tests_data/firefox_bookmarks.html` from
  [andriyor/bookmarks-parser at c5a7a94](https://github.com/andriyor/bookmarks-parser/blob/c5a7a94bb20b10f2123c9f6fbc7633cb05332c07/tests/tests_data/firefox_bookmarks.html).
  Real upstream Firefox export: 9 URLs, nested folders, a folder description,
  base64 favicons, non-ASCII titles. Project declares MIT on PyPI; no license
  file was found at the repository root during this survey.
- `chrome.html`: unmodified sibling `chrome_bookmarks.html` at the same commit.
  Real upstream Chrome export: 8 URLs, nested/empty folders, toolbar attributes,
  query strings/fragments, non-ASCII titles and favicons.
- `linkding-upstream.html`: unmodified
  [linkding import test resource](https://github.com/sissbruecker/linkding/blob/27b7303baf41bb28babc610ac8eaa486e1ddfab5/bookmarks/tests/resources/simple_valid_import_file.html)
  (MIT): 3 entries with tags/descriptions and second/millisecond/microsecond dates.
- `linkding-conflicts.html`: generated by executing the actual linkding exporter
  functions at the same commit, replacing only the Django model import with a
  lightweight object. Two snapshots of one URL have different titles,
  descriptions, notes and case-sensitive tags. Synthetic bookmark values, real
  producer and format. The source's original LF/CR line endings are preserved.

All fixtures are public samples, not anyone's personal bookmarks. Synthetic adversarial
inputs in tests are labeled by their test names and supplement these real formats.

## Additional upstream version variants

`linkding-v1.15.html`, `linkding-v1.31.html`, `linkding-v1.47.html` were generated
by the unmodified exporter modules stored in `tests/upstream/`, from the named
release tags. The generation uses a lightweight bookmark object, with no Django
application or network calls. They cover pre-note exports, older archive tags,
missing modification dates, newer archive tags, read/private flags and Markdown
notes. `tests/browserbookmarks/upstream/generate_fixtures.py` reproduces them offline.

`tests/upstream/` contains the original parser and exporter modules at those
three tags; their MIT license is in [`licenses/linkding-MIT.txt`](../../../licenses/linkding-MIT.txt)
(see also the `notewrench browser-bookmarks` section of [THIRD_PARTY.md](../../../THIRD_PARTY.md)). Tests strip only
Django imports and inject actual pure tag/normalization helpers. They exercise
real upstream format functions, not a running server or model validation.

## Chromium's Safari format regressions

`safari-no-root.html`, `safari-folders.html`, and `safari-reading-list.html` are
the raw HTML literals from `Bookmarks_NoTopLevelDL`, `Bookmarks_Folders`, and
`Bookmarks_ReadingList` in
[Chromium's Safari importer tests](https://chromium.googlesource.com/chromium/src/+/f82317413d635d3dfc1abf79597fce56eb9eceff/components/user_data_importer/utility/safari_data_importer_unittest.cc).
Pinned revision: `f82317413d635d3dfc1abf79597fce56eb9eceff`. Whitespace inside
the C++ raw literals is preserved. These are real upstream regression inputs,
not exports captured from a live Safari session in this project.

The source explicitly documents that real-world Safari exports omit the outer
DL. The cases also cover nested/empty folders, Reading List identifiers, and
negative/pre-epoch timestamps. Chromium's BSD license is included in
[`licenses/chromium-BSD-3-Clause.txt`](../../../licenses/chromium-BSD-3-Clause.txt). Chromium/Safari itself was not launched.

v1.15.0 `2c7848aa46cffbd2cfe98628842bf06004d17dd3`,
v1.31.0 `695b0dc300772add2069d7857b99b989da2305b7`,
